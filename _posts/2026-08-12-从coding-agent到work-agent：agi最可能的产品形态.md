技术一旦开始扩散，没有人知道用户最终的使用姿势。如果说今年我自己最想看到的产品是什么，那一定是一个all-in-one的agent。但是却没有想到这个all-in-one的agent竟然是以coding agent的形式出现的。

从Claude的cowork，到ChatGPT for work，再到国内Workbuddy的爆火，各各类AI办公产品层出不穷，“work”似乎成为国内外一个共识场景。Greg Brockman在采访时表示，GPT work和Codex其实用的是同一套的Harness，底层也是coding agent，只是对办公场景做了专门的适配。Claude官方也承认，Cowork和Claude code使用的是同一套agent架构。但是由于需要适配开发者和知识工作者的工作流需要，work模式和coding模式在UX、git可见性以及沙盒模式的设置上都有差异。那为什么是coding agent先跑通，以及为什么chat不行呢？

## 为什么是coding agent

在Claude code和codex发布后，Anthropic和codex在这两家公司内部得到了广泛的应用，并且现实的趋势是一致的：Coding Agent在工作场景中的采用率是非常高的。最开始是开发者，然后是非开发者。最开始是代码任务，然后是招聘、财务等各种其他的更通用的任务。在 OpenAI 内部，从 2025 年 11 月到 2026 年 6 月，所有职能的中位员工 output tokens 至少增长了 10 倍；其中法律岗位大约增长 13 倍，研究岗位超过 50 倍。从任务的难度看，2025 年 12 月，35.4% 的活跃个人用户至少提交过一次“人类需要 1 小时以上才能完成”的任务；到了 2026 年 5 月，这个比例上升到 70.2%。比例的提升意味着AI极大程度的提高了生产了。AI从回答任务进阶为一个可以分析、可以执行、可以根据反馈进行修复的智能工作伙伴。（看一些对anthropic员工的采访说，一个产品只有在内部得到了广泛的应用，才会正式推为线上产品）我毫不怀疑，这也是Claude cowork诞生的最简单的原因。

回到coding agent的本身，其自身特点促成了其的成功。首先，“[知识工作是在软件中进行的，比如使用各种商业app，浏览器，电子表格和数据库。coding agent天然适合这种环境](https://arxiv.org/html/2604.13107v1)”。其次，相比只能调用预设工具的传统 Agent，Coding Agent 还可以通过编写脚本、调用 API、组合程序等方式，动态创建工具并扩展自己的行动空间，因此具有更强的通用性和可扩展性。最后，软件环境通常能够提供较为明确、即时的执行反馈，例如程序是否运行成功、测试是否通过、API 是否返回预期结果、系统状态是否发生正确变化。这种可验证的反馈使 Coding Agent 能够形成“执行—观察—验证—修正”的闭环，并通过不断迭代来完成任务。

# Coding Agent for work的技术扩散

Coding Agent的技术扩散是快而不均的。它的用户大概可以分为三类，AI公司的使用者、组织用户使用者以及个人用户使用者。在各类人群中，Codex官方调研得到了以下数据。这个数据说明，Coding agent的使用并不也并不是少数人用一点，而是“少部分人先进入非常深的 Agent 工作模式”。

[](https://x.com/beverlyssd/article/2087169954822926763/media/2087114042146205696)

从具体的工作类型来看，非技术工作的使用场景还是集中在文档的产出上，如产品呢、销售和市场的任务大头都是知识产出。但区别于以往chat使用时的查询输出模式，用户更倾向于向agent指派一个完整的任务，如给Codex一些文件，让codex分析这些文件，同时搜索和这些文件相关的资料，从而产出文件。而技术场景的使用无疑是最为广泛的，无论是OpenAI自己还是普通企业。

[](https://x.com/beverlyssd/article/2087169954822926763/media/2087162177421717505)

但是最有意思的是这类产品的应用与公司权力关系的互动。在普遍的预期中，AI在公司内部的应用一直对应着一个简单的预期“初级员工用 AI 写代码、高级员工用 AI 做管理”。但是，在在普通的企业用户中，高管的使用场景集中在知识产出和工程运维中。在OpenAI内部，高管的使用场景才集中在协作上。我们可以推测，这种预期的权力分化是在AI渗透率接近饱和时才会出现的。其次，无论是普通公司还是在AI公司内部，随着职级的降低，知识产出任务的占比是下降。这也可以侧面说明，AI时代，更稀缺的是判断，而不是执行。

# Work agent的关键指标

区域别传统互联网产品的指标，如DAU、MAU等关键指标，对work agent来说，应该看的指标更多。Work Agent的核心价值在于生产力的提升，最关键的指标应该是task complexity，意味着比如说人工在不需要AI协助的情况下完成这项工作所需要的时间。

并发度也是一个应该关心的指标，即有多少agent在一起工作，因为这意味着人机协作关系的转变。

工作流复用（skill / plugin），这意味着一个企业或者团队将自身上下文、潜移默化的习惯进行了系统化 ，代码着一个企业AI化的程度。
